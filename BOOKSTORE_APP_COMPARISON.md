# Bookstore App: Android vs. iOS Feature Comparison

This document provides a detailed walkthrough of the features available in the Android and iOS versions of the Bookstore (BookShare) application as of March 2026. Both apps are built on modern native frameworks (Jetpack Compose for Android and SwiftUI for iOS) and share a common backend API.

## 🛠️ Detailed Walkthrough

### 1. Authentication & Onboarding
*   **Android:** Features a dedicated `OnboardingScreen` and `AuthScreen`. It uses a phone-based OTP system. The UI is being updated to follow a "Warmth & Trust" design philosophy with custom illustrations.
*   **iOS:** Implements `AuthenticationView` and a `MainTabView`. It also uses the same phone OTP system, with secure token storage using the native **iOS Keychain**.

### 2. Discover & Home Feed
*   **Both Platforms:** Implement a searchable feed of books.
*   **Filters:** Users can filter by Genre, Condition (New, Good, etc.), and Availability.
*   **Personalization:** Carousels for "Available Near You," "Popular in Your Groups," and "Recently Added."
*   **Android Specific:** The Home screen is currently undergoing a redesign to improve visual hierarchy and add "Continue Reading" sections.

### 3. Book Management (My Library)
*   **ISBN Scanning:** Both apps support barcode scanning using `ISBNScannerView` (iOS) and `AddBookScreen` (Android) to fetch metadata automatically via OpenLibrary/Google Books APIs.
*   **Manual Entry:** Detailed forms for manually entering book details (Title, Author, Genre, Condition, Location).
*   **Lending Status:** Real-time visibility of which books are "Available," "Lent," or "Currently Unavailable."

### 4. Book Clubs (Groups)
*   **Social Connectivity:** Users can discover groups (Office, Friends, Neighborhood) and join them using unique invite codes.
*   **Group Management:**
    *   **Android:** Includes `CreateGroupScreen`, `GroupDetailScreen`, and `GroupMembersScreen`.
    *   **iOS:** Includes `GroupHomeView`, `GroupDetailView`, and `GroupService` for discovery.
*   **Invite System:** Both platforms support generating and sharing invite links/codes to bring others into private groups.

### 5. Transaction & Lending Lifecycle
One of the most complex features implemented on both platforms is the secure book exchange:
*   **Borrowing Flow:** A borrower sends a request with a duration and a custom message.
*   **Approval:** The owner receives a notification and can Approve, Reject (with reason), or Ignore the request.
*   **Secure Exchange (OTP):**
    *   A unique OTP is generated by one party (e.g., Owner for handover).
    *   The second party must enter this OTP in their app to verify the physical exchange.
    *   This protects both parties and updates the book's "Lent" status in the system.
*   **Return Flow:** A similar OTP process is used when the book is returned to the owner.

### 6. Transaction Messaging (Chat)
*   **Both Platforms:** Feature a built-in messaging system tied to specific transactions.
*   **Purpose:** Allows owners and borrowers to coordinate meeting times, locations, and discuss book condition without sharing phone numbers (based on privacy settings).
*   **Implementation:** Polling-based chat in iOS (`ChatView.swift`) and real-time capable `TransactionChatScreen.kt` in Android.

## 📱 Feature Gaps & Visual Details

While both apps share the same core functionality, the **Android version (post-redesign)** includes several specific visual and information details that are currently absent from the **iOS version**.

### 1. Home Screen Discoverability
*   **Android:** Features multiple curated horizontal carousels like "Available Near You," "Popular in Your Groups," and "Recently Added."
*   **iOS:** Uses a simpler, single vertical grid for all books. It lacks the horizontal sections for progressive discovery.

### 2. Book Detail Depth
*   **Android:** Displays **Distance from user** (e.g., "2.3 km away") and **Response Time** (e.g., "Usually responds in 2h"). It also features a **Lending Terms** card detailing "Max duration" and "Deposit requirements."
*   **iOS:** Focuses on core book info and owner name. It does not yet show proximity data or owner responsiveness stats.

### 3. Visual Indicators
*   **Condition Dots:** Android uses a 5-dot rating system for book condition, whereas iOS uses a single icon with text (e.g., "Star Icon: Good").
*   **Book Interaction:** Android's redesign includes 3D tilt/shadow effects for book covers in the detail view to provide a more premium feel.
*   **Status Badges:** Android tiles include explicit availability badges on top of the cover art, while iOS uses a bottom-right dot indicator.

### 4. User Profile & Impact
*   **Android:** Includes a "Your Impact" section with stats like "Lent Out" vs. "Books Added" in a card format, along with a "Recent Activity" summary.
*   **iOS:** Uses a standard list-based layout for stats. It lacks the location display (e.g., "📍 Brooklyn, NY") and the activity summary found in Android.

## 🎨 Design & Technical Differences

### Android Implementation
*   **Tech Stack:** Jetpack Compose, Kotlin, MVVM with Hilt, Coil for images.
*   **Design:** Material 3 (M3). Currently focusing on custom micro-animations (card spring effects, logo bounces) and rich "Empty States" with illustrations.
*   **Architecture:** Heavily uses ViewModel and Repository patterns with `StateFlow`.

### iOS Implementation
*   **Tech Stack:** SwiftUI, Swift, MVVM, native `URLSession`.
*   **Design:** Native HIG (Human Interface Guidelines). Uses a `ThemeManager` for Dark/Light mode unification.
*   **Security:** Uses **KeychainManager** for secure handling of JWT access and refresh tokens, which is more robust than simple file-based storage.

## 🚀 Known Gaps & Future Improvements

1.  **Android:** "MyLibrary" book tap and "Group Detail" was previously reported as basic/placeholders; however, recent updates show these are now mostly functional with the new Redesign.
2.  **iOS:** Push notification integration using APNs is fully configured in the code, whereas Android is still transitioning to a more robust FCM implementation in its latest redesign.
3.  **Real-time:** The chat system on both platforms is currently functional but could be improved with WebSockets for a better real-time experience instead of polling/manual refreshes.
